URL shortener in Go

Eddy WM’s four-part Gin + Redis build, drawn as two request paths.

Gin :9808 go-redis v8 6 h TTL
01

How it is wired

Two routes, one process, one store.

Write · create a short link
1
Client
POST /create-short-url with { long_url, user_id }
2
Gin engine main.go
routes to CreateShortUrl; binds the JSON, 400 if a field is missing
3
GenerateShortLink
pure function: sha256(url + user) → base58 → 8 chars
4
SaveUrlMapping
takes user_id and ignores it — only code → url is written
5
Redis
SET code → long_url, expires in 6 h
Read · follow a short link
6
Client
GET /<code> — same host, no redirect domain
7
Gin engine
routes to HandleShortUrlRedirect; reads the path param
8
RetrieveInitialUrl
looks up the code; a miss panics, so “unknown” becomes a 500
9
Redis → browser
returns the URL, handler answers 302, browser follows it

Both lanes share the same Gin instance and the same store singleton. There is no queue and no second service.
